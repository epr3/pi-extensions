# Model presets own atomic model and thinking selection

The sticky thinking-level clamp in Pi's raw model cycling should be handled in this repo by a new `model-presets` Extension package, not by patching Pi core or relying only on `enabledModels`. The package owns **Atomic model presets** in a Pi settings **Model preset catalog** shaped as keyed `presets` plus explicit `cycle`, exposes an explicit command plus `Ctrl+Shift+M` shortcut for cycling/selecting them, renders through built-in select/status UI, and performs **Preset thinking repair** only when a raw Pi model selection matches a configured preset; duplicate provider/model matches require `repairDefault: true`, while invalid presets warn instead of silently inventing fallbacks. Package code has no active preset defaults; installable examples live in `packages/pi-config/settings.json`, starting with a coding-oriented cycle: `openai-codex/gpt-5.5:medium`, `openai-codex/gpt-5.3-codex-spark:low`, `opencode-go/minimax-m3:high`, and `opencode-go/deepseek-v4-pro:high`. This trades universal magic for predictable user-configured behavior while preserving Pi's built-in raw model selector.
