# Define Web Tool Boundaries

The Readability-to-Markdown and Jina fallback decisions below are superseded by [Prompt-directed extraction with session-owned source artifacts](../../packages/web-fetch/adr/2026-09-10-prompt-directed-extraction-with-session-artifacts.md); the other web-tool boundaries remain in force.

`web_search` will initially target Google Custom Search only, with credentials read from environment variables plus `~/.pi/agent/auth/web-search.json`, while `web_fetch` will ship the full inspired extraction scope: HTML/plain-text extraction, Readability-to-Markdown conversion, PDF extraction, response-size caps, timeouts, and Jina Reader fallback for hard-to-extract pages. We will keep `web_search` and `web_fetch` as separate Extension packages and load them in both the repo's shipped config/docs and this machine's active `~/.pi/agent/settings.json`; the original subagents grant-point text for `researcher` is superseded by `packages/subagents/adr/2026-07-09-remove-researcher-subagent-type.md`, so web research is now modeled as parent-agent direct tool use rather than a built-in Subagent type. This favors a self-contained research workflow and dependency isolation over a provider abstraction or minimal fetch MVP.
