# Verify extension lifecycle with a real-Pi smoke workflow

Extension lifecycle behavior is verified by a real-Pi smoke workflow in `scripts/pi-smoke/` rather than by extending the package fakes or by treating inspection as evidence. The workflow runs the actual `pi` CLI with the packages' extensions loaded, answers its model requests from a deterministic local stub over the OpenAI chat-completions protocol, and checks Pi's own `--mode json` session events plus an extension-side lifecycle probe, in an isolated agent directory, session store and `HOME`. This supplements — and does not replace — the deterministic package-owned Vitest suites: fake `ExtensionAPI` harnesses stay the fast, hermetic contract tests, while the smoke workflow is the only source that shows Pi's real extension loading and cleanup, session/tool/run event order, the dual result contract as Pi stores it in a session, and session-branch reuse across processes. The trade-off is an unhermetic, hand-run workflow that needs the `pi` CLI on `PATH` and that cannot verify TUI-only behavior (the statusline footer, the interactive `question` dialog), real provider/sampling behavior, network lifecycle, LSP child processes or Subagent child sessions; those stay explicitly unverified until a pty driver or a targeted scenario exists. Lifecycle defects are claimed only from smoke evidence, never inferred from coverage gaps, and the workflow stays out of `pnpm test` and `verify:ext` so a missing Pi runtime reads as "not run" instead of a passing check.
