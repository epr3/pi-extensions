# Default Subagent Model Overrides Parent Model

When `subagents` config names a **Default Subagent model**, a **Subagent run** uses that model instead of the parent Pi session's active model; per-**Subagent type** defaults override the shared `subagents.defaultModel`, and if no subagent default is configured the run falls back to the **Parent model**. The setting uses an exact `provider/model` string rather than Pi root-style provider/model keys or CLI fuzzy matching, trading a tiny parser for concise config; an unresolvable configured reference is treated as absent and falls back to the **Parent model** instead of failing the run, with a warning carried in tool details and UI notification rather than prefixed to the subagent result text. This is surprising because Pi sessions normally inherit the current model, but it makes the setting useful for cost/latency isolation; the rejected fallback-only behavior would almost never take effect because tool contexts normally already have `ctx.model`, while a shared-only setting would force read-only and write-capable subagents onto the same default, and a fail-fast invalid-reference policy would make subagents brittle during model config churn.
