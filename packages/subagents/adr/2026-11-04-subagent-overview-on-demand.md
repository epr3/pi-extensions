# Revise the Inline-Only Presentation Restriction into an On-Demand Subagent Overview

`/subagents` — which previously answered with a textual notification listing — opens a read-only, dismissible (Esc/Enter), scrollable **Subagent overview** overlay in the TUI: one row per **Subagent run** naming run id, **Subagent type**, description, and textual state, active runs first then terminal and `outcome unavailable` rows, newest first within each group, current-session runs combined with reconstructed **Branch-local outcomes** and deduped by run id; where a TUI overlay is unavailable the textual notification stays. Hard to reverse once users habituate to `/subagents` as the inspection path, though the command remains usable everywhere. Surprising — earlier design documentation restricted run presentation to inline rows with "no separate dashboard", and dashboards usually drift toward becoming primary surfaces. Trade-off: an on-demand answer to "what is running right now (and what ran on this branch)" costs nothing while closed, but the inline **Compact run rows**, **Launch receipts**, and **Attributed completions** stay the authoritative per-run record; the overview carries no activity tails, no result bodies, and no run controls, so it cannot become the place where runs are operated.

Revision (ticket 0003): while open, the overview re-renders on its session's run lifecycle transitions — queued, running, and terminal states, ordering, and the empty state — so the on-demand answer stays current without closing and reopening it. Updating is keyed to the **Originating session**: session shutdown or replacement deactivates the open overview before that session's runs settle, so a dying session's terminal states never appear in its overview or in a successor's. This adds a live-update behavior for the open component only; the on-demand, read-only, no-controls bounds above stand — the overview still carries no activity tails, no result bodies, and no run controls, and has no persistent presence when closed.
