# Enforce the Single-Level Subagent Boundary Exclusively

Subagent runs are exactly one level deep, enforced structurally: every sub-session — built-in (`explore`, `general`) and custom alike — is created without the fixed safety-exclusion tools (`Agent`, `get_subagent_result`, `stop_subagent`, `question`), and the same names are unconditionally removed from any custom definition's toolset, so only the parent Pi coding agent launches, retrieves, stops, and questions. No nesting machinery exists: there is no hidden `_parent_id` tool parameter, no LLM-echoed parent identity, no depth computation, and no parent lookup at spawn time; the boundary is a tool-set subtraction, visible in configuration, that custom frontmatter cannot override.

This is surprising because the retired nesting design treated nesting as a supported mode to be bounded (`allowNestedSubagents`, `maxSubagentDepth`); the alternative was keeping that machinery and defining how deep delegation is allowed. Shipped reality is the stricter choice: the Claude-style spec's single-level decision made nesting itself out of scope, and a structural exclusion is simpler to reason about, test, and keep safe than depth accounting keyed on an LLM-echoed courier — an echoed identifier is untrusted in principle, and hidden tool parameters bake a spawn-time contract into every caller before any enforcement exists. The trade-off is that no path exists for a Subagent to delegate even when a user would want one, and revisiting this means a new parameter surface rather than flipping a capability flag.

Supersedes `2026-07-09-hidden-params-for-nesting-identity.md` (hidden `_parent_id` params, depth limits, and the `plan` / `general-purpose` built-ins it described were never shipped). The shipped boundary preserves the **Same-turn fan-out** decision unchanged: the parent still delegates multiple sibling runs in one assistant turn via repeated `Agent` calls under the shared concurrency cap — fan-out is parent-side parallelism, not nesting.
