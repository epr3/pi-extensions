# Attributed Background Completion via Pi Custom Message

A terminal background **Subagent run** sends one **Attributed completion** to its **Originating session** as a Pi custom message (`customType: "subagent-outcome"`), queued with `deliverAs: "followUp"` when the parent is busy and turn-triggering when idle, with run identity in message `details` and the **Bounded result text** (or marked partial output) as message content. This is surprising because Pi has no scheduling/messaging API dedicated to detached outcomes — the built-in custom-message channel is extended with run attribution instead of a new protocol; the alternatives were a user message (would misattribute a Subagent outcome as something the user typed) or a notify toast (would create no model context and no continuation). Busy/idle is tracked from Pi's `agent_start`/`agent_settled` lifecycle, not `hasUI`, because RPC is headless yet continues the conversation while print/json bind no UI and cannot promise a later turn — those modes get an explicit diagnostic at launch instead of silent non-delivery. Delivery is bound to the originating session: `session_shutdown` stops queued and running runs, deactivates delivery (idempotently), and stale `pi`/`ctx` errors after replacement are treated as cancellation; delivery is at-most-once under normal operation, and explicit retrieval with `get_subagent_result` remains for missed deliveries.
