## Operator annotation (written after the recorded runs, referencing the transcripts above)

- **Coverage:** all 5 × 2 = 10 runs completed without harness errors; no prerequisite was missing (typescript-language-server 5.3.0 ran; baseline revision `580785b` present in history). Every task's final answer was factually correct for both variants, verified against the fixture sources.
- **Headline observation (this one draw):** with `gpt-6.1-terra` at thinking `low`, first-choice tool selection came out **identical between the two guidance variants on every task** — grep first for the textual task, `lsp_document_symbols`/`lsp_workspace_symbols` first for orientation and semantic tasks. A plausible reading is that the baseline guidance (which the spec notes already expressed an LSP preference in several places) was already sufficient to trigger LSP-first choices for this model on this task set, so the revised wording's first-choice push added nothing observable here. This is one observation run per cell, not a stable result, and not a finding about the guidance's value in general — see the next note on where the variants did visibly differ.
- **Spontaneous fallback/recovery (fallback scenario, intra-task):** in the baseline `T1-definition` run the first `lsp_workspace_symbols` call errored (ENOENT — the model had named a nonexistent Routing file `src/index.ts`), and the model fell back through `bash`/`find` to a corrected workspace-symbol query and a document outline before answering (transcript `...-baseline-T1-definition.jsonl`). The revised run of the same task recovered more directly (workspace symbols → grep → document symbols, no errored tool result). No task had server failure as its dedicated trigger (no missing-executable scenario was run — the environment had a healthy server); recovery was exercised via the model's own bad Routing-file guess on one side.
- **Recorded wall clock, no conclusion drawn:** baseline runs took ~25–30 s each, revised runs ~8–10 s, under the same model/thinking/allowlist. Provider-side latency during the run is the likely cause; both variants' reasoning traces differ in length, and the harness does not control for it.
- **Variability caveat:** identical tool orders across variants on a single draw are not evidence of a stable effect (or absence of one). Rerunning with `LSP_EVAL_THINKING` variations or a different model may diverge; use the exact commands in `scripts/lsp-tool-choice-eval.README.md`.
